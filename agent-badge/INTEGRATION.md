# Agent Badge — integration notes

This is **The Badge** (MIT, © curisama) used as the device OS for a combined
Waveshare ESP32-S3-Touch-AMOLED-1.75C firmware. Codey is **not** part of this
firmware.

## Status (2026-11-09)

- The Badge base builds and runs on the board (ESP-IDF v5.5.4, 32 MB flash
  confirmed by `esptool flash_id`, 8 MB OPI PSRAM).
- The launcher's third page has **Pet / Codex / Sand** with custom RGB565A8
  icons generated by `tools/gen_agent_icons.py`.
- **Codex**: Usage rings + today tokens/cost, Codex Radar IQ (parsed from
  `codexradar.com`), Status (bridge/battery/plan/radar/sync). Swipe left/right
  inside the app. Data comes from `tools/run_codex_bridge.sh` on port 8790.
- **Sand**: real `sand_sim.c` physics (12 materials, fire/acid/water), tilt
  gravity, touch brush, two-row 12-material palette + clear, LVGL canvas 466x466.
  Touch is handled by the canvas itself (LVGL coordinates); the palette is a
  normal LVGL button row on top. A top "material + ☰" button opens a radial
  menu: S1/L1/S2/L2 (scenes in the tail of the `rec` partition), IMG (fetches
  the bridge's `sand_scene.rle`), X. Scene RLE is about 3 KB per slot.
- The Codex fetch task needed 10 KB stack (6 KB overflow corrupted LVGL and
  rebooted on app open).
- Toolchain lives in `../.toolchain/`; use `./tools/dev.sh build|flash|monitor`.

## Architecture decisions

- Base: The Badge — ESP-IDF 5.5, LVGL 9.5, launcher (`main/app.h`), power
  management, BLE HID, WiFi, recorder/USB, exact 1.75C board support.
- Claude Desktop Buddy is Arduino; its **BLE NUS JSON protocol** is ported to
  the Badge's Bluedroid stack and its pet/screens are ported to LVGL.
- Codex Island is ESP-IDF + LVGL 9.5; its Usage / Radar / Distributed Radar /
  Status pages are ported into `app_codex`. Data is fetched over **WiFi HTTP**
  from a macOS bridge (preferred), so Claude Desktop keeps the single BLE NUS
  link. BLE for Codex is optional and would use a second GATT connection.
- Falling Sand is ESP-IDF and normally renders direct to the panel; this port
  instead runs its physics on a 466x466 LVGL canvas (simpler and safe next to
  the launcher/Codex app).
- Do not mix two BT host stacks: Badge uses Bluedroid, Codex Island uses
  NimBLE. Codex therefore goes over WiFi. Claude NUS is added as another GATT
  service in the same Bluedroid stack.

## Partition / flash

The Badge assumes a **32 MB** 1.75C (`sdkconfig.defaults`:
`CONFIG_ESPTOOLPY_FLASHSIZE_32MB`), 6 MB factory app + 24 MB recordings.
Some 1.75C units are 16 MB; if so, `partitions.csv` must be re-cut (e.g. 6 MB
app + 4 MB recordings + assets) before flashing. Check with:

```bash
python3 -m esptool --chip esp32s3 -p /dev/cu.usbmodem101 flash_id
```

## Codex bridge

```bash
agent-badge/tools/run_codex_bridge.sh   # HTTP on :8790, reads ~/.codex
```

The badge asks `http://auto:8790/codex.json` (and `sand_scene.rle`). After
joining WiFi it broadcasts `AGENTBADGE/1` to UDP 8790; the bridge answers with
the LAN address it sees from the badge, so the Mac IP does not need editing.
If discovery is blocked, `port_http_get` falls back to `192.168.50.13`.
The bridge caches usage for 60 s and refreshes Radar from `codexradar.com`
every 30 min (60 s retry on failure). The device's old Codey WiFi credentials
are migrated from the NVS namespace `codey` into the Badge slots on first boot.

PNG import: put a PNG at `agent-badge/tools/sand_import.png`; the bridge resizes
it to 116x116, maps colours to materials and serves RLE on `/sand_scene.rle`.

USB import is **not** ported: the Badge's TinyUSB exposes the recordings
partition as a read-only FAT and has no teardown; a writeable FAT MSC would
replace the recorder and needs a reboot path. The bridge/HTTP import above is
the working equivalent.

To keep the bridge running after logout/reboot:

```bash
agent-badge/tools/install_codex_bridge_launchd.sh
```

## Build

ESP-IDF v5.5.4, target esp32s3. The workspace-local toolchain lives in
`../.toolchain/`:

```bash
export IDF_TOOLS_PATH="$PWD/../.toolchain/espressif"
. ../.toolchain/esp-idf/export.sh
cd agent-badge
idf.py set-target esp32s3
idf.py build
```

First build fetches LVGL 9.5, the Waveshare BSP/QMI8658 components and TinyUSB
into `managed_components/`.
