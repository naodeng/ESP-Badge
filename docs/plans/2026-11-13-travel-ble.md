# 出行速度表 BLE 实施计划

目标：把已试做的速度／运动航向界面接入固件 app_t 和共享 NimBLE host；新增独立出行入口，不更改已有索引、分区、录音和配置。

范围：速度、运动航向、精度、明确标记的模拟数据；本轮不实现地图、真实路线规划、IMU 融合或原生 iOS App。浏览器发送器支持具备 Web Bluetooth 的浏览器；iOS 需要后续原生伴侣。

设计：纯 C travel_data 事务解析 20 字节 v1 帧；ble_travel 在 critical section 内维护会话快照，GATT 要求加密写入；LVGL 仅在 UI tick 读快照。5 秒无新定位清空显示；拒绝重复、倒序、旧会话、越界和未知版本。速度低于 1.5 m/s 时隐藏运动航向。导航保留到后续协议版本，避免未实现能力被误认为可用。

任务：
- [ ] 先写数据解析回归，确认缺失功能失败；实现长度、字段、时序与新鲜度校验。
- [ ] 新增 BLE 服务和前台生命周期，统一注册；连接代次隔离迟到回调，退出清空数据。
- [ ] 追加出行应用与矢量图标，保留原有入口编号；隐藏暂停 UI，退出停止连接。
- [ ] 新增浏览器发送器（模拟明确标记，定位保留样本年龄），文档说明手机兼容范围。
- [ ] 原生协议/UI/蓝牙边界测试、既有相关回归、ESP-IDF 构建；分别记录未执行的设备项目。

审查重点：无效帧不刷新有效数据年龄；重连不复活旧会话；模拟不冒充定位；缺失速度不冒充静止；退出不访问已释放 LVGL 对象。实施由本会话直接完成，不烧录设备。
