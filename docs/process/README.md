# 项目过程与迭代约定

## 当前项目结构是长期结构

主仓库长期包含固件、Moto GPS iOS App、网关服务、共享协议和本地调试工具；不是临时聚合目录。对外产品名和唯一固件名固定为 `Jarvis_OS`，iPhone App 名为 `MOTO GPS`，Worker 名为 `moto-gps-gateway`。

## 变更流程

1. 先核对产品边界、当前入口和上游许可。
2. 固件协议变更要同时检查 iOS、共享代码、fixtures 和固件端解析。
3. NVS、分区、BLE 配对或用户文件格式变更要先写兼容/备份方案，再改代码。
4. 配置和 Secret 要区分本地、Wrangler 和 Cloudflare 生产环境；Secret 不写进文档示例的真实值。
5. 改动后根据用户当前目标执行构建、测试或设备验收，并明确哪些只在模拟器、哪些是真机。
6. 发布包只输出一个 `Jarvis_OS.bin`，同时记录 SHA-256、设备分区偏移和构建版本。

## 过程文档规则

- 当前事实写在根 README、产品说明、架构和 docs 的开发/部署/调试页面。
- 计划文档用日期命名，完成后写结果，不要让旧 TODO 看起来仍是当前任务。
- 上游原文、旧设计与移除功能说明可归档，但需标为历史资料。
- 二进制发布产物和机器配置不提交。可重建的 manifest、校验和生成步骤应留在仓库。

## 本轮收口记录

本轮将单一固件和 Moto GPS iOS/后端/共享代码集中到主仓库，移除旧产品入口，并保留历史许可与两个调试工具目录。安装采用应用分区单地址写入，维持原分区表、NVS 和用户存储。设备端 BLE 和 iPhone 真机联调结果应写入 `docs/project-status.md`，不得由主机编译推断。
